# 設計書 — そらへ（モノと思い出を手放すためのWebアプリ）

## 概要

「そらへ」は単一ページの静的Webアプリである。フレームワークやビルド工程を持たず、
`index.html` / `styles.css` / `app.js` の3ファイルで構成される。供養アニメーションは
p5.js 等の外部ライブラリに依存せず、ブラウザ標準の **Canvas 2D API + requestAnimationFrame**
で実装する（過去に p5.js のインスタンス初期化が不安定だったため、依存を排除した経緯がある）。

本設計は現行実装（v1.4.0）の構造を反映する。

---

## アーキテクチャ

```
index.html         画面構造（タブ / 2つのフォーム / 演出オーバーレイ / バージョン表示）
  ├─ styles.css    見た目（星空背景 / フォーム / 演出オーバーレイ / レスポンシブ）
  └─ app.js        振る舞い（タブ切替 / 入力処理 / メッセージ生成 / 供養アニメーション）
```

- 外部依存は Google Fonts（Shippori Mincho / Zen Kaku Gothic New）のみ。
- 実行時のデータフローはすべてブラウザ内で完結し、ネットワーク送信を行わない。

### 画面レイヤー構成（z-index）

```
[0] #stars           固定背景の星空
[1] .site-header / .tabs / .stage / .site-footer   通常UI
[50] .ceremony       演出オーバーレイ（全画面・既定は hidden）
      ├─ [1] #canvas-holder > canvas   供養アニメーション描画面
      ├─ [2] .ceremony-message         お別れメッセージ
      └─ [3] .speed-control            速度スライダー
[100] .version-badge 左下のバージョン表示
```

`.ceremony` は `display:flex` を持つため、非表示時は `.ceremony[hidden] { display:none !important }`
で確実に隠す（`hidden` 属性が `display:flex` に上書きされる問題への対処）。

## コンポーネントと責務（app.js）

### 1. タブ切り替え
- `.tab` のクリックで `data-tab`（`thing` / `memory`）に対応する `.panel` のみ表示する。

### 2. 写真アップロード（モノ）
- クリックおよびドラッグ&ドロップに対応。
- `FileReader` で DataURL 化し、`<img>` プレビューへ反映。
- 併せて `Image` オブジェクトを生成して保持（`uploadedImage`）。アニメーションのピクセル抽出に用いる。
- 画像以外のファイルは無視する。

### 3. お別れメッセージ生成（モック）
- 生成AIは使わず、定型文の配列からルールに基づき選択する。
- `buildThingMessage(name, message)`:
  - メッセージ本文がある場合は「気持ちに触れる」文面群から選ぶ。
  - 名前があれば文面に差し込む（なければ「わたし」）。
- `buildMemoryMessage(text)`:
  - 本文が60文字以上なら「より寄り添う」文面群から選ぶ。
- 将来 API 連携する場合は、これらを非同期関数に差し替えれば呼び出し側は不変。

### 4. 供養アニメーション（Canvas 2D）

#### Particle クラス
写真の1サンプル点、または思い出の光の粒を表す。

主なプロパティ:
- `homeX, homeY`: 初期位置（写真上の位置 / 中央付近のランダム位置）。
- `r, g, b`: 芯の色。写真の色を少しオレンジ寄りに補正して保持。
- `glowR, glowG, glowB`: まとう暖色の光暈（オレンジ〜金）。
- `delay`: 発つまでの遅れ。`HOLD_TIME + (1 - yNorm) * RISE_SPAN + ランダム`。
  画面下部（`yNorm≒1`）ほど早く、上部ほど遅く発つ。
- `riseSpeed`（上昇 px/秒）, `driftX`（横ゆらぎ）, `wobble`（揺れ位相）。
- `life`: 1→0 の寿命。`fadeDur` 秒かけて減衰。
- `resting`: `life>=1`（＝まだ発っていない・静止中）か。

主なメソッド:
- `update(t)`: 経過秒 `t`（速度倍率込み）から位置・寿命・サイズを更新。
- `draw(ctx)`:
  - 静止中は写真の色そのままを不透明で描画（元写真が見える）。
  - 発ったあとは、暖色の光暈を加算合成（`lighter`）、芯は通常合成で写真の色を保つ
    （＝白飛び防止）。

#### buildParticles(mode, image, W, H) → Particle[]
- **モノ**: オフスクリーン `<canvas>` に写真を縮小描画し、`getImageData` でピクセルを走査。
  一定間隔（`grid=4`px）でサンプルし、透明度が低い点を除いて Particle を生成。
  `yNorm = yy / sampleH` を付与。
- **フォールバック / 思い出**: 写真から粒が0個の場合、または思い出モードでは、
  中央付近に暖色主体の光の粒を約340個配置する。これにより粒が0個になることを防ぐ。

#### startCeremony(mode, image, message)
1. オーバーレイを表示し、メッセージを隠す。差出人ラベルを設定。
2. 直前のアニメーション（`rafId`）を停止。
3. `#canvas-holder` を空にし、`window` 実寸のキャンバスを新規生成。
4. `buildParticles(...)` で粒を生成。写真の表示矩形 `photoRect` を算出。
5. フォールバックタイマー（規定秒）を設定：万一進まなくても必ずメッセージを出す。
6. `requestAnimationFrame` ループ `loop()` を開始。

#### loop()（描画ループ）
- `elapsed = 実経過秒 × animSpeed`。
- `holding = elapsed < HOLD_TIME`:
  - **HOLD 中**: 背景を毎フレーム塗り直し、元写真 `image` を `photoRect` に描画。
    終盤1秒で `globalAlpha` を落として薄れさせる。粒は描かない。
  - **上昇中**: 背景を半透明で塗り重ね（残像＝尾）、各粒を `update`→`draw`。
- メッセージ表示条件: `!holding` かつ（生存粒が全体の6%未満 or 一定秒経過）。
- 条件成立で `revealMessage(message)` を一度だけ呼ぶ。

#### revealMessage(message)
- 二重表示を防止（既に表示中なら何もしない）。
- フォールバックタイマーを解除。
- メッセージブロックを表示し、本文を `setInterval` で一文字ずつ追記する。

### 5. 演出の操作
- 速度スライダー `#speed` の `input` で `animSpeed` を更新（`loop` が即座に反映）。
- 閉じるボタンでオーバーレイを隠し、`rafId` を停止、キャンバスを破棄、フォームを初期化。

### 6. バージョン表示
- `APP_VERSION` 定数を左下のバッジ `#version-badge` に反映する。

## タイミング定数

| 定数 | 値（目安） | 意味 |
|------|-----------|------|
| `HOLD_TIME` | 2.2 秒 | 元写真/光を静止して見せる時間 |
| `RISE_SPAN` | 2.5 秒 | 下から順に発ち始めるまでの広がり |
| `fadeDur`   | 3.6 秒 | 各粒が消えるまでの時間 |
| フォールバック | 16 秒 | 万一進まないときにメッセージを出す上限 |

`animSpeed`（スライダー, 既定1.0）で全体が伸縮する。通常速度で演出全体は約8秒程度。

## データモデル

永続データは持たない。実行時のみ以下を保持する。

- `uploadedImage: Image | null` — アップロードされたモノの写真。
- `animSpeed: number` — 演出速度倍率。
- `rafId: number | null` — 実行中アニメーションフレームID。
- `particles: Particle[]` — 現在の演出の粒（`startCeremony` 内ローカル）。

---

## エラーハンドリング

- **写真未選択で送信**: 演出を開始せず、アップロード領域の枠色で警告。
- **思い出テキスト未入力で送信**: 演出を開始せず、テキスト欄の枠色で警告。
- **画像ピクセルの読み取り失敗**（`getImageData` 例外）: 粒生成を光の粒フォールバックに切り替え。
- **演出が進まない**: フォールバックタイマーで必ずメッセージを表示。

---

## テスト戦略

自動テストは持たない軽量構成のため、手動確認を基本とする。

- **タブ切替**: 2タブの表示切替と選択状態。
- **モノ**: 写真選択（クリック/DnD）→ 送信 → 写真表示 → 粒化・上昇 → メッセージ。
- **思い出**: テキスト入力 → 送信 → 光の粒上昇 → メッセージ。
- **バリデーション**: 写真なし / テキストなしでの送信時の警告。
- **速度スライダー**: 進行速度が変わること。
- **閉じる**: オーバーレイが閉じ、フォームが初期化されること。
- **レスポンシブ**: スマホ幅でレイアウトが崩れないこと。
- **静的検証**: `node --check app.js` による構文チェック。

## 設計判断の記録

- **p5.js を採用しない**: インスタンスモードの初期化タイミングで setup 未発火・粒0件の不具合が
  発生したため、標準の Canvas 2D + rAF に置き換え、初期化の不確実性を排除した。
- **芯は通常合成・光暈のみ加算**: 全粒を加算合成にすると明るい写真で白飛びするため、
  芯は写真色を保ち、光暈だけ加算して「光っているが色が残る」表現にした。
- **写真を先に見せてから分解**: いきなり粒にするより、元の姿を見せてお別れの間を作るほうが
  情緒的だと判断した（HOLD フェーズの導入）。
